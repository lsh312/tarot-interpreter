# Tarot Interpreter

**Live API:** https://tarot-interpreter.onrender.com | [Interactive docs](https://tarot-interpreter.onrender.com/docs)

> Hosted on Render free tier — first request after idle may take ~30s to cold start.

A RAG-powered tarot reading API. Each reading draws real cards from a shuffled deck (with random orientation), retrieves their symbolic meanings from a vector database, and passes them to Claude for a personalised interpretation.

## How It Works

```
User request
     │
     ▼
TarotAgent draws N cards at random (upright or reversed)
     │
     ▼
Card meanings retrieved from Chroma vector DB (sentence-transformers embeddings)
     │
     ▼
Claude Haiku generates interpretation via streaming API call
     │
     ▼
FastAPI returns structured JSON response
```

## Spread Types

| Endpoint | Cards | Use case |
|---|---|---|
| `POST /reading/daily` | 1 | Energy of the day — no question needed |
| `POST /reading/three-card` | 3 (Past / Present / Future) | Fast answer to a specific question |
| `POST /reading/celtic-cross` | 10 | Detailed answer to a specific question |

## Tech Stack

| Layer | Technology |
|---|---|
| LLM | Claude Haiku (`claude-haiku-4-5-20251001`) via Anthropic SDK |
| Embeddings | `sentence-transformers/all-MiniLM-L6-v2` (local, no extra API key) |
| Vector DB | Chroma (persisted to `models/chroma_db/`) |
| API | FastAPI + Uvicorn |
| Data | 78-card JSON dataset with images |
| Tests | pytest + FastAPI TestClient |
| CI | GitHub Actions |

## Quickstart

### 1. Clone and set up environment

```bash
git clone <repo-url>
cd tarot-interpreter

# conda (recommended)
conda env create -f environment.yml
conda activate tarot-interpreter

# or pip
pip install -r requirements.txt
```

### 2. Add your Anthropic API key

```bash
# .env (git-ignored)
ANTHROPIC_API_KEY=sk-ant-...
```

Get a key at [console.anthropic.com](https://console.anthropic.com).

### 3. Ingest the card data

This embeds all 78 cards into the Chroma vector database. Only needs to run once.

```bash
python -m src.ingest
```

To rebuild from scratch:

```bash
python -m src.ingest --reset
```

### 4. Run the API

```bash
uvicorn src.api.main:app --reload
```

The API is now available at `http://localhost:8000`. Interactive docs at `http://localhost:8000/docs`.

## API Reference

### `GET /health`

```json
{ "status": "ok" }
```

### `POST /reading/daily`

No request body.

```json
{
  "spread_type": "single_card",
  "question": null,
  "cards": [
    {
      "position": "The Card",
      "name": "The Moon",
      "orientation": "Reversed",
      "keywords": ["confusion", "fear", "illusion"],
      "meaning": "...",
      "image_filename": "major_18.jpg"
    }
  ],
  "interpretation": "..."
}
```

### `POST /reading/three-card`

```json
// Request
{ "question": "Should I pursue this new opportunity?" }

// Response — same shape as above, cards array has 3 items
// positions: "Past", "Present", "Future"
```

### `POST /reading/celtic-cross`

```json
// Request
{ "question": "How should I approach my career right now?" }

// Response — cards array has 10 items
// positions: "Present", "Challenge", "Past", "Future", "Above",
//            "Below", "Advice", "External Influences", "Hopes and Fears", "Outcome"
```

## Design Decisions

**Why sentence-transformers instead of an embedding API?**
Anthropic does not offer an embeddings API. Using a local model (`all-MiniLM-L6-v2`) avoids adding a second API provider and keeps the ingest step free.

**Why Chroma instead of a managed vector DB?**
The corpus is small (78 cards, static). Chroma persists to disk with no infrastructure overhead. Swapping to Pinecone or another provider would only require changing `config.yaml` and a small adapter.

**Why sync route handlers instead of async?**
The `anthropic` SDK's streaming client is synchronous. FastAPI runs sync handlers in a thread pool automatically, so sync handlers are the correct choice here — using `async def` with a sync blocking call would stall the event loop.

**Why prompt caching on the system prompt?**
The system prompt is identical across all requests. Anthropic's prompt caching (`cache_control: ephemeral`) stores it server-side for up to 5 minutes, reducing both latency and cost on repeated calls.
